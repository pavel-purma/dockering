# Changelog

All notable changes to Dockering are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Spec changes are tracked separately in [`docs/spec/CHANGELOG.md`](docs/spec/CHANGELOG.md).
New sections are generated by [release-plz](https://release-plz.dev) from conventional commits
in the release PR (REL-011); edit the wording there before merging.

## [0.1.0] - unreleased

The first release. release-plz fills in the date and adds new sections above this one.

### Added

- Dual licence MIT OR Apache-2.0 (`LICENSE-MIT`, `LICENSE-APACHE`) (REL-001).
- Third-party notices in `THIRD_PARTY_LICENSES.html`, generated by `cargo about` and bundled in every package (REL-002).
- `cargo deny` licence allowlist, advisories, bans, and source checks (REL-003).
- CI: lint (fmt, clippy, NFR-001 blocking-call check, cargo-deny, actionlint), tests on Linux/Windows/macOS, Docker integration tests, and release builds for all six targets (NFR-040).
- Release workflow: signed Windows installer and zip, notarised macOS `.dmg`, and Linux `.deb`/`.AppImage`/`.tar.gz`, with build-provenance attestations and `SHA256SUMS`, published to a draft GitHub Release.
- `cargo xtask` helpers: `check-blocking`, `record-fixtures`, `package`, `dist`, `icons`, `update-manifest`, `sign-manifest`, `gen-update-keys`, and `checksums`.
- Platform bootstrap scripts (`scripts/bootstrap.sh`, `scripts/bootstrap.ps1`) and app icons.
- Windows installer built with Inno Setup: per-user by default (all users with `/ALLUSERS`), x64 and arm64. It replaces the MSI and NSIS packages (REL-020…027).
- In-app update checks against GitHub Releases. You can turn them off in Settings (UPD-001…012).
- Release automation with release-plz: a release PR with the version bump and changelog, then a `vX.Y.Z` tag when it merges. PR titles are checked for conventional commits (REL-010, REL-011).
- winget manifests for `PavelPurma.Dockering` and a workflow that submits every stable release (REL-040, REL-041).
- New app icon (REL-050).
